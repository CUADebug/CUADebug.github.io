Why diagnosis is hard

The visible failure is often not the first mistake.

CUA errors can hide in a tiny perception cue, an interaction mechanic, a planning decision, or a system artifact many steps before the final symptom.

Method

From failed trajectory to repairable root cause.

CUADebug couples tool-guided multimodal inspection with structured RCA, cautious memory retrieval, and debugger-guided re-rollout.

01

Inspect

Pair the before-screen, reasoning, grounded action, execution state, and after-screen.

02

Localize

Search backward for the first causal divergence, not the last visible symptom.

03

Structure

Emit root step, subtype, grounded evidence, correction, and inspected-step summaries.

04

Repair

Inject the diagnosis into re-rollout and measure both error avoidance and task success.

Re-execution protocols

What each re-rollout condition changes.

Five guidance packages are compared under single and continual re-execution. Recovery is measured on the failed Claude 4.5 Sonnet trajectories; Overall Acc adds recovered failures to 203 initial successes over 361 tasks.

Single re-rollout

Restart near the diagnosed cause.

The agent restarts one step before the root-cause step. Machine RCA uses its predicted restart step; the other conditions use the human-labeled step.

Continual re-rollout

Continue after the 50-step failure.

Claude 4.5 Sonnet resumes from step 51. The comparison includes history-only continuation, self-debugging, machine RCA, CUADebug, and human-annotation guidance.

How to read New + Fixed. The manuscript defines the first number as cases where the original critical error was fixed but a new critical error appeared, and the second as cases fixed without a new critical error. These counts are transcribed verbatim rather than independently recomputed by this static page. Because restart sources and prompt formats differ, the single protocol compares complete re-execution packages rather than isolating diagnosis quality.
